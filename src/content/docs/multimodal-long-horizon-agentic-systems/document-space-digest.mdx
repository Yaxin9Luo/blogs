这批 notes 的中心问题很清楚：**如何把多模态设计生成从一次性 prompt 变成一个可评测、可诊断、可自我改进的 long-horizon agentic system**。

## 总体脉络

1. 主文档先提出方向：多模态 in、多模态 out 的系统不缺单点模型能力，缺的是面向设计任务的 harness、feedback signal 和 artifact-level verification。
2. 海报生成拆分把问题落到具体 artifact：学术海报不是宣传图，核心是信息重组、版式密度、图文证据、可编辑性和内容准确性。
3. Verifier & Benchmark 把“看起来好不好”拆成 deterministic checks、VLM critic、rubric、reference pool、paper quiz 和 benchmark 可视化。
4. 路线 2 的迭代 notes 记录了从人工调 prompt 到 coding agent 根据 eval 自动优化 pipeline 的演进。
5. 每周同步记录了中期关键问题：排版几乎收敛后，文本准确性、重复率、section-to-panel 内容分配和 memory 机制变成主要瓶颈。

## 核心研究判断

### 1. Artifact-first，而不是 agent-first

如果目标是 poster、slides、web page 或 video，先定义 artifact contract 比先写 agent prompt 更重要。contract 需要规定内容覆盖、图表使用、视觉密度、可编辑结构、渲染方式和失败条件。

### 2. Harness 是把主观判断工程化的接口

“这张海报不好看”对 agent 没有用；“信息架构缺少 method -> evidence -> takeaway 的路径、三个 panel 重复同一结论、图表引用没有对应 source pack”才是可执行反馈。

### 3. Benchmark 不能替代 verification

Benchmark 负责横向比较系统能力；verification 负责判断单个 artifact 是否可交付。长程多模态任务必须同时有两者。

### 4. Reference pool 会改变优化方向

如果参考样本全是视觉墙或截图墙，generator 会把“图多”误解成“质量高”。reference 应按 artifact archetype 拆开：text-heavy synthesis、theory board、benchmark/table-first、GUI/video 等。

### 5. 自动迭代的难点会迁移

早期问题是布局、overlap、渲染失败；中期问题会转向文本重复、事实错误、panel 内容分配、source grounding 和 metric 权重错位。
