## Background

These papers are usually not just about placing images next to a language model. They deal with a harder structure problem: pages contain layout, paragraphs, charts, formulas, reading order, and cross-page dependencies. When reading, first decide whether the method actually models document structure or merely wraps a visual encoder with a language interface.

<Insight title="Questions to Ask First">
Do visual tokens preserve layout relations? Can text tokens map back to page coordinates? Does the model only answer questions, or can it generate editable, locatable, and verifiable document artifacts?
</Insight>

## Core Questions

- How is the input document represented: full-page image, cropped region, OCR token, layout token, or a mixed representation?
- How are vision and text aligned: cross-attention, unified token sequence, coordinate embedding, or post-processing?
- Does the training objective cover real tasks: understanding, extraction, QA, layout recovery, generation, and editing?

## Method Breakdown

1. Input encoding: record image resolution, patch strategy, OCR usage, and coordinate encoding.
2. Fusion layer: record where and how visual features enter the language model.
3. Output constraint: record whether the model emits structured JSON, HTML, Markdown, coordinates, or natural language.
4. Evaluation setup: record datasets, metrics, failure cases, and whether there is human usability evaluation.
